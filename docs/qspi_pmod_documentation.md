# qspi_pmod.v — Architecture and Execution Reference

## 1. Purpose

`qspi_pmod.v` is a simulation-only behavioral model of the TinyTapeout QSPI PMOD board, which carries one QSPI NOR flash and two QSPI PSRAMs. It replaces the real hardware in cocotb testbenches, providing the same bus interface that `core.v` / `qspi_ctrl.v` will talk to on silicon.

The model has two operating layers that reflect the real board's lifecycle:

- **Phase A (pre-init, SPI mode):** An RP2040-like host drives SPI setup commands — exit flash continuous mode, enter flash continuous mode via `0xEB`, put both PSRAMs into QPI mode via `0x35`. Only single-bit SPI (`IO0`/MOSI + `IO1`/MISO) is used here.
- **Phase B (runtime, QPI mode):** The core owns the bus. Flash is read in continuous QPI mode (no command byte). PSRAMs are read and written in QPI mode (2-nibble command + address + data).

---

## 2. Physical Interface

```
input  wire       qspi_sck      — shared serial clock (driven by host or core)
input  wire [2:0] qspi_cs_n     — active-low chip selects: [0]=flash, [1]=RAM A, [2]=RAM B
inout  wire [3:0] qspi_dq       — quad data bus: IO0/MOSI, IO1/MISO, IO2, IO3
```

The model drives `qspi_dq` through a tri-state gate:

```verilog
assign qspi_dq = dq_oe ? dq_out : 4'bzzzz;
```

`dq_oe` is asserted only during read phases. During command, address, write-data, and dummy phases the model releases the bus so the master can drive it.

---

## 3. Memory Arrays and Initialization

```verilog
reg [7:0] flash [0:FLASH_BYTES-1]   // default 64 KiB
reg [7:0] ram_a [0:RAMA_BYTES-1]    // default 64 KiB
reg [7:0] ram_b [0:RAMB_BYTES-1]    // default 64 KiB
```

All three arrays are zero-filled first, then loaded from hex files using `$readmemh`:

```verilog
$readmemh("mem/flash.hex", flash);
$readmemh("mem/rama.hex",  ram_a);
$readmemh("mem/ramb.hex",  ram_b);
```

The paths are relative to the directory vvp runs from (the `test/` directory). The hex files are byte-addressed, one byte per line, and are pre-generated by the Makefile's `prepare_mem` target before simulation starts — `$readmemh` runs at time 0 before any cocotb test code executes.

Optional plusargs override the initial mode flags without needing an init sequence:

```
+FLASH_CONTINUOUS=1    sets flash_continuous_mode = 1
+RAMA_QPI=1            sets ram_a_qpi_mode = 1
+RAMB_QPI=1            sets ram_b_qpi_mode = 1
```

---

## 4. Persistent Mode Flags

These flags survive across CS transactions and track the current mode of each device:

| Flag | Meaning | Changed by |
|---|---|---|
| `flash_continuous_mode` | Flash skips command byte on next CS assertion | Set by `0xEB` (SPI path), cleared by `0xFF` |
| `flash_write_enable` | Flash accepts erase/program commands | Set by `0x06`, cleared by `0x04` or after use |
| `ram_a_qpi_mode` | RAM A interprets commands as QPI (4-bit) | Set by `0x35`, cleared by `0xF5` |
| `ram_b_qpi_mode` | RAM B interprets commands as QPI (4-bit) | Set by `0x35`, cleared by `0xF5` |

---

## 5. State Machine Overview

The model uses a 5-bit `state` register and two `always` blocks clocked on opposite SCK edges, plus CS-edge tasks.

### 5.1 State Encoding

**QPI / runtime states (Phase B):**

| State | Value | Description |
|---|---|---|
| `ST_IDLE` | 0 | No device selected |
| `ST_QPI_CMD` | 1 | Receiving 2-nibble QPI command byte |
| `ST_QPI_ADDR` | 2 | Receiving 6-nibble (24-bit) QPI address |
| `ST_QPI_DUMMY` | 3 | Clocking dummy nibbles (master drives, model ignores) |
| `ST_QPI_RDATA` | 4 | Driving read data nibbles onto the bus |
| `ST_QPI_WDATA` | 5 | Sampling write data nibbles from the bus |

**SPI / pre-init states (Phase A):**

| State | Value | Description |
|---|---|---|
| `ST_SPI_CMD` | 6 | Receiving 8-bit command serially on IO0 |
| `ST_SPI_ADDR` | 7 | Receiving 24-bit address serially on IO0 |
| `ST_SPI_DUMMY` | 8 | Clocking dummy bits (model ignores) |
| `ST_SPI_RDATA` | 9 | Driving read data serially on IO1/MISO |
| `ST_SPI_WDATA` | 10 | Sampling write data serially from IO0 |
| `ST_SPI_ID` | 11 | Driving JEDEC/manufacturer ID bytes on IO1 |
| `ST_SPI_STATUS` | 12 | Driving status register byte on IO1 |

### 5.2 The Two Always Blocks

The model is split into an **input side** and an **output side**:

```
posedge qspi_sck  — input side:  sample data driven by the master, advance state
negedge qspi_sck  — output side: set up data to be driven by the model
```

Standard SPI/QSPI timing: the master (`qspi_ctrl.v` or the Phase A host) drives output data before the rising edge so the slave (this model) can sample it on the rising edge. Conversely, the slave drives response data on the falling edge so the master can sample it on the next rising edge. The two always blocks mirror this split: posedge handles input (master → model), negedge handles output (model → master).

### 5.3 CS Edge Handlers

CS assertion and de-assertion are handled outside the SCK clock domain:

```verilog
always @(negedge qspi_cs_n[0]) set_selected(DEV_FLASH);
always @(negedge qspi_cs_n[1]) set_selected(DEV_RAMA);
always @(negedge qspi_cs_n[2]) set_selected(DEV_RAMB);

always @(posedge qspi_cs_n[0] or posedge qspi_cs_n[1] or posedge qspi_cs_n[2])
    if (qspi_cs_n == 3'b111) deselect();
```

**`set_selected(dev)`** (called on CS falling edge):
- Records which device is selected (`selected_dev`)
- Resets all per-transaction state: `cmd`, `addr`, `byte_buf`, `bit_count`, `nib_count`, `dummy_left`, `low_nibble_phase`, `id_index`
- Releases the bus: `dq_oe = 0`
- Chooses the entry state based on mode flags:
  - Flash with `flash_continuous_mode = 1`: enters `ST_QPI_ADDR` (no command byte needed)
  - PSRAM with `ram_x_qpi_mode = 1`: enters `ST_QPI_CMD`
  - Any device in initial SPI mode: enters `ST_SPI_CMD`

**`deselect()`** (called when all CS lines go high):
- Clears `selected_dev` to `DEV_NONE`
- Releases the bus: `dq_oe = 0`
- Resets counters and returns `state` to `ST_IDLE`

## 6. Phase A Execution — Pre-Init SPI Transactions

In Phase A, `host_active = 1` in the testbench and `qspi_init.py` drives the SPI bus through the `host_*` pins. The model is in SPI mode for all three devices.

### 6.1 Flash: Exit Continuous Mode (`0xFF`)

The negedge of CS0 fires `set_selected(DEV_FLASH)`. Because `flash_continuous_mode = 0` at power-on, `set_selected` enters `ST_SPI_CMD`.

Each of the 8 posedge SCK events is handled by the input always block in `ST_SPI_CMD`, which shifts IO0 into `cmd` one bit at a time. When `bit_count` reaches 7 (the last bit), the completed byte `0xFF` is decoded: `flash_continuous_mode` is cleared to 0 and `state` moves to `ST_IDLE`.

The posedge of CS0 fires `deselect()`.

### 6.2 Flash: Enter Continuous Mode (`0xEB`)

This is a simplified SPI path that achieves the `flash_continuous_mode = 1` side-effect without implementing the full 1-4-4 quad protocol.

The negedge of CS0 fires `set_selected(DEV_FLASH)`, entering `ST_SPI_CMD`.

**Command phase (8 posedge SCK):** The input always block shifts IO0 into `cmd`. When `bit_count` reaches 7 and the completed byte is `0xEB`, `state` moves to `ST_SPI_ADDR`.

**Address phase (24 posedge SCK):** The input always block shifts IO0 into `addr` one bit at a time. When `bit_count` reaches 23, the completed address is latched. Because `cmd == 0xEB` and the selected device is flash, `flash_continuous_mode` is set to 1, `dummy_left` is loaded with 8, and `state` moves to `ST_SPI_DUMMY`.

**Dummy phase (8 posedge SCK):** The input always block decrements `dummy_left` on each posedge. These 8 SCK cycles consume the mode byte sent by the caller (e.g. `0xA0`). The model does not inspect the mode byte value; it simply counts down. When `dummy_left` reaches 1, `state` moves to `ST_SPI_RDATA`.

**Read phase (8 posedge SCK):** The first negedge SCK after the state transition to `ST_SPI_RDATA` triggers the output always block, which reads `flash[addr]` into `byte_buf`, drives `byte_buf[7]` onto IO1 (MISO), and asserts `dq_oe`. IO0, IO2, and IO3 remain Z. The caller clocks 8 posedge SCK events to read back 1 byte. After the 8th bit, `addr` increments.

The posedge of CS0 fires `deselect()`.

After this transaction `flash_continuous_mode = 1` for all future CS0 assertions.

### 6.3 PSRAM: Enter QPI Mode (`0x35`)

The negedge of CS1 fires `set_selected(DEV_RAMA)`. Because `ram_a_qpi_mode = 0`, `set_selected` enters `ST_SPI_CMD`.

**Command phase (8 posedge SCK):** The input always block shifts IO0 into `cmd`. When `bit_count` reaches 7 and the completed byte is `0x35`, `ram_a_qpi_mode` is set to 1 and `state` moves to `ST_IDLE`.

The posedge of CS1 fires `deselect()`.

The same sequence is repeated for CS2 to set `ram_b_qpi_mode = 1`.

After both transactions `ram_a_qpi_mode = 1` and `ram_b_qpi_mode = 1`.

### 6.4 SPI Output Timing

In states `ST_SPI_RDATA`, `ST_SPI_ID`, `ST_SPI_STATUS`, the model drives only `IO1` (MISO, `qspi_dq[1]`). The other three bits are left as `z`:

```verilog
dq_out <= {2'bzz, byte_buf[7 - bit_count], 1'bz};
```

Callers must not read the full 4-bit `qspi_dq` as an integer; they should extract only bit 1.

## 7. Phase B Execution — Runtime QPI Transactions

In Phase B, `host_active = 0`. The core owns the bus. The model expects QPI protocols for all transactions.

### 7.1 Flash Continuous Read

Entry condition: `flash_continuous_mode = 1`.

The negedge of CS0 fires `set_selected(DEV_FLASH)`. Because `flash_continuous_mode = 1`, `set_selected` enters `ST_QPI_ADDR` directly — no command byte is expected.

**Address phase (6 posedge SCK):** The input always block shifts all 4 bits of `qspi_dq` into `addr` on each posedge, assembling the 24-bit address high-nibble first. `nib_count` tracks progress from 0 to 5. When `nib_count` reaches 5, `dummy_left` is loaded with `FLASH_CONT_DUMMY_NIBBLES` (6) and `state` moves to `ST_QPI_DUMMY`.

**Dummy phase (6 posedge SCK):** The input always block decrements `dummy_left` on each posedge. The bus is released by the model (`dq_oe = 0`); the core drives it but the model ignores the values. When `dummy_left` reaches 1, `state` moves to `ST_QPI_RDATA`.

**Data phase:** Data is driven on negedge SCK and sampled by the core on the following posedge SCK. Each byte takes two SCK cycles.

- On the first negedge after entering `ST_QPI_RDATA`: the output always block reads `flash[addr]` into `byte_buf` (blocking read), drives `byte_buf[7:4]` onto all 4 bits of `qspi_dq`, asserts `dq_oe`, and sets `low_nibble_phase = 1`. The core samples these 4 bits on the next posedge.
- On the second negedge: the output always block drives `byte_buf[3:0]`, clears `low_nibble_phase`, and increments `addr`. The core samples the low nibble on the next posedge.
- This pair repeats for each subsequent byte without any pause.

The posedge of CS0 fires `deselect()`, ending the stream at whatever byte boundary the core chooses.

Total overhead before data: 6 address nibbles + 6 dummy nibbles = 12 QPI clock cycles.

### 7.2 PSRAM QPI Read

Entry condition: `ram_a_qpi_mode = 1` (or `ram_b_qpi_mode` for CS2).

The negedge of CS1 fires `set_selected(DEV_RAMA)`. Because `ram_a_qpi_mode = 1`, `set_selected` enters `ST_QPI_CMD`.

**Command phase (2 posedge SCK):** The input always block assembles the command byte from two nibbles. On the first posedge `cmd[7:4]` is loaded from `qspi_dq` and `nib_count` becomes 1. On the second posedge `cmd[3:0]` is loaded, `nib_count` resets to 0, and `state` moves to `ST_QPI_ADDR`.

**Address phase (6 posedge SCK):** Identical to the flash address phase. When `nib_count` reaches 5, the command is checked: if `cmd` is `0x0B` or `0xEB`, `dummy_left` is loaded with `PSRAM_QPI_DUMMY_NIBBLES` (6) and `state` moves to `ST_QPI_DUMMY`.

**Dummy phase (6 posedge SCK):** Identical to the flash dummy phase. When `dummy_left` reaches 1, `state` moves to `ST_QPI_RDATA`.

**Data phase:** Identical to the flash data phase, but reads from `ram_a[]` instead of `flash[]`.

The posedge of CS1 fires `deselect()`.

### 7.3 PSRAM QPI Write

The negedge of CS1 fires `set_selected(DEV_RAMA)`, entering `ST_QPI_CMD`.

**Command phase (2 posedge SCK):** Same as the read command phase. When `nib_count` reaches 1 and the command byte is complete, `state` moves to `ST_QPI_ADDR`. For a write, `cmd` is `0x02` or `0x38`.

**Address phase (6 posedge SCK):** Same nibble-shift as reads. When `nib_count` reaches 5, the command is checked: if `cmd` is `0x02` or `0x38`, `state` moves directly to `ST_QPI_WDATA` — there is no dummy phase for writes.

**Write data phase:** Data is driven by the core and sampled by the model on each posedge SCK. Each byte takes two posedge SCK events.

- On the first posedge of a byte pair (`low_nibble_phase = 0`): the input always block latches `qspi_dq` into `byte_buf[7:4]` and sets `low_nibble_phase = 1`.
- On the second posedge (`low_nibble_phase = 1`): the input always block calls `mem_write_byte` with `{byte_buf[7:4], qspi_dq}` as the byte value, increments `addr`, and clears `low_nibble_phase`. The write to the array happens immediately (blocking call inside the task).

This pair repeats for every byte the core sends. The model stays in `ST_QPI_WDATA` until CS goes high.

The posedge of CS1 fires `deselect()`.

Bytes are written one at a time as each nibble pair completes. `addr` increments after each written byte, so multi-byte writes are contiguous.

## 8. Nibble Ordering and Bus Width Summary

All QPI transfers are **high nibble first**:

| Field | Width | Encoding |
|---|---|---|
| QPI command byte | 2 nibbles | `[7:4]` first, then `[3:0]` |
| 24-bit address | 6 nibbles | `[23:20]`, `[19:16]`, ..., `[3:0]` |
| Dummy | N nibbles | Don't-care, bus released |
| Read/write data byte | 2 nibbles | `[7:4]` first, then `[3:0]` |

In SPI mode (Phase A), only `IO0` (MOSI) is used for input and only `IO1` (MISO) is used for output. `IO2` and `IO3` float as `z`.

---

## 9. Bus Direction Control

The model holds `dq_oe = 0` (bus released) by default. It asserts `dq_oe = 1` only when actively driving read data:

| Condition | `dq_oe` | Who drives `qspi_dq` |
|---|---|---|
| CS deasserted | 0 | Nobody (Z) |
| Any command/address/dummy/write phase | 0 | Master / core |
| `ST_QPI_RDATA` | 1 | Model drives all 4 bits |
| `ST_SPI_RDATA`, `ST_SPI_ID`, `ST_SPI_STATUS` | 1 | Model drives IO1 only; IO0, IO2, IO3 = Z |

The negedge `default` handler actively clears `dq_oe` in any non-read state, ensuring the bus is promptly released:

```verilog
default: begin
    if (state != ST_QPI_RDATA && state != ST_SPI_RDATA
        && state != ST_SPI_ID && state != ST_SPI_STATUS) begin
        dq_oe <= 1'b0;
        dq_out <= 4'h0;
    end
end
```

## 10. Key Parameters

| Parameter | Default | Meaning |
|---|---|---|
| `FLASH_BYTES` | 65536 | Flash array size in bytes |
| `RAMA_BYTES` | 65536 | RAM A array size in bytes |
| `RAMB_BYTES` | 65536 | RAM B array size in bytes |
| `FLASH_CONT_DUMMY_NIBBLES` | 6 | Dummy nibble count for flash continuous reads |
| `PSRAM_QPI_DUMMY_NIBBLES` | 6 | Dummy nibble count for PSRAM QPI reads |

`FLASH_CONT_DUMMY_NIBBLES = 6` absorbs both the 2-nibble mode byte and 4 real dummy cycles that the flash datasheet specifies. `qspi_ctrl.v` is parameterized to match both counts.

## 11. Simulation Timing Notes

The model is purely event-driven on SCK edges — it has no dependency on the core clock. This means the QSPI clock rate (which `qspi_ctrl.v` derives from the core clock) has no effect on model correctness; only the relative ordering of SCK edges and CS edges matters.

The first read nibble of a QPI or SPI read is driven during the negedge that occurs when `qspi_ctrl.v` transitions through `ST_NEXT_SEG` before entering `ST_SHIFT` for the read phase. This negedge comes from `qspi_ctrl.v` lowering SCK when leaving the dummy phase, which gives the model one half-cycle of setup time before the master clocks the first posedge.

For write transactions, `qspi_ctrl.v` must keep `dq_oe` asserted through the posedge of the last write nibble. Releasing it on the same non-blocking update as the last `qspi_sck <= 1` causes a race: the model's `@(posedge qspi_sck)` fires after the NBA region (where `dq_oe` is already 0), so `qspi_dq = Z` is sampled. The fix is to release `dq_oe` in `ST_NEXT_SEG`, one cycle after the last nibble's posedge.
